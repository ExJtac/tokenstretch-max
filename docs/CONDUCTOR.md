# tokenstretch MAX: Conductor design

**Status: project map, standalone verification gate, provider-neutral planning/execution, reusable patterns and optional local text offload implemented.** The owner deferred provider-specific benchmark work so the main build proceeds independently of any one provider. The foundation preserves upstream history and licensing while separating the `tsmax` package, command, and state from tokenstretch. Runtime stays Python 3.11+ and standard library only.

## Flow and ownership

`goal → skill suggestions + project map → top-model plan → fresh light/mid task → verify → done or escalate`

Small core modules own indexing, planning, scheduling, verification, and patterns. Adapters own every provider-specific path, model choice, command, hook, and configuration change. Reuse the existing queue's claims and file-overlap checks, brief formatting, usage normalization, and installer manifests; do not replace those systems. Start with sequential tasks; concurrency requires disjoint file ownership and independent gates.

The core has no preferred AI provider. Select a tool explicitly, negotiate its capabilities, and resolve light/mid/top models through that adapter. New providers implement the same request/response interface. Missing tools or unsupported permission modes are reported directly; never substitute another provider, model or weaker permission mode. Claude is one optional adapter, not a build dependency or reviewer. The map and verification gate require no AI at all.

| Command | Behavior |
|---|---|
| `tsmax map build` | Build or incrementally refresh this project's local index. |
| `tsmax map query "where is login"` | Return at most 10 ranked `file:line` results with short symbol/summary text. |
| `tsmax map status` | Report indexed files, freshness, skipped files, and extraction limits. |
| `tsmax map serve` | Expose query/status through read-only MCP on stdio; no listening socket. |
| `tsmax map install --tool TOOL` | Preview adapter-owned MCP/hook changes; `--apply` uses backup and undo. |
| `tsmax verify [--run]` | Preview detected checks; explicit `--run` executes them offline and records content-bound results. |
| `tsmax plan "<goal>"` | Suggest matching patterns, then use the selected tool's top model to write `.tsmax/plan.md`. |
| `tsmax run` | Work in a separate Git worktree, verify each task, and ask before applying its reviewed changes. |
| `tsmax run --prepare` | Prepare or inspect staging without model calls; missing dependencies need explicit local setup. |
| `tsmax skills suggest "<task>"` / `save TASK` | Search local patterns; preview saving a verified approach, with explicit apply. |
| `tsmax local status` / `summary` / `handoff` / `commit-message` | Inspect an existing local runtime or preview a text operation; `--run` authorizes one inference. |
| `tsmax undo [MANIFEST]` | Restore a recorded change or task checkpoint, preserving later edits or refusing on conflict. |

## Local state and project map

Project `.tsmax/` holds `map.sqlite3`, `decisions.jsonl`, `plan.md`, validated `plan.json`, queue state, approved verification commands, and per-run results. Records contain relative paths, SHA-256 hashes, symbols/line numbers, imports, deterministic one-line summaries, decisions, task dependencies, attempts, check exits, durations, and reported usage. Bounded diagnostic logs and optional screenshots stay local. `~/.tsmax/` owns private backups and manifests; neither store reads tokenstretch's state. Adding a local Git exclusion is itself backed up and undoable.

Enumerate tracked and eligible untracked files; respect ignores and exclude generated/binary/oversized files, `.tsmax`, credentials, and login stores before opening. One read policy covers indexing, excerpts, imports, and checkpoints: adapter-owned credential exclusions plus secret-file exclusions, no-follow opens, no symlink ancestors or escaping paths. Recheck identity when opening; ambiguous files are skipped. Use hashes as authority for changes, deletions and renames. Initially avoid Git subprocesses: repository config can redirect Git into excluded files. Git-diff hints are deferred; guarded traversal handles local ignore rules and reports unsupported patterns. Re-extract changed files transactionally. Python uses `ast`. Prioritize JavaScript/TypeScript functions, classes, arrows, types and imports with a bounded lexer; label these results approximate rather than claiming a full parser. Proper language-parser support is an early follow-up, subject to the standard-library constraint. Rank local path, symbol, import, and text matches deterministically. Summaries need no model; defer embeddings.

MCP exposes no write or shell tools. The adapter chooses a supported stdio MCP integration or a small hook; installer plans show the exact change and preserve existing configuration.

## Verification, planning, and execution

Detect existing test, lint, and typecheck commands without installing dependencies. Record approved argv, required checks, and acceptance criteria before execution; project configuration is executable input, not automatic authorization. The standalone gate runs in the selected root; the runner supplies its staging worktree and rechecks the original project after application. Bound output/time and terminate the process group. Checks must be synchronous: detached jobs are unsupported, and descendant quiescence is not verified. Require OS-level external-network isolation, a temporary home and reduced environment; this does not contain host filesystem access. Missing tools, zero collected tests, reported skipped tests, timeout, or absent supported test evidence mean **incomplete**. Bind results to observed source/test/configuration hashes, commands, executable metadata and dependency locks. Dynamically loaded external inputs remain a limitation; this is not a hermetic build. Compare hashes before and after checks, immediately before applying, and after application. Edits invalidate results; worker output cannot certify its own gate. Optional screenshots are deferred and will require an installed browser with external requests and redirects blocked.

The plan names tasks, dependencies, allowed files, acceptance tests, and checks; validate structure and paths locally. Workers receive only their spec, map slice, and necessary excerpts in a fresh official CLI session. Only the gate completes a task. Two failed inexpensive attempts allow one stronger-model attempt, using bounded, redacted failures plus spec/map slices. Failed escalation becomes `needs-review`; missing dependencies/authentication or quota failures stop. Persist attempts before dispatch, including interrupted attempts; resume cannot reset caps or replay uncertain work. Explicit authorization covers planning and worker CLI calls with task/run call limits. Unknown usage stays unknown; dollar caps are advisory unless the provider enforces them.

**Adapter contract:** `run_headless_task` has a separate explicitly authorized Conductor purpose, retaining legacy benchmark protections; `bench=True` cannot bypass it. Typed capabilities, requests and responses separate provider facts from orchestration. Run the user's own logged-in CLI with its existing login and verified permission modes. MAX never opens, copies, relocates, or proxies credentials; the CLI authenticates itself. Unsupported adapters, versions, environments and required modes refuse before dispatch. Current offline capability profiles are verified on macOS; absent capabilities are not inferred from another provider.

**First execution release:** use a dedicated Git worktree from a recorded commit; leave existing dirty work untouched. A worktree separates proposed edits, **not host or credential access**: native CLI permissions and approvals remain necessary. Show the complete diff and gate results, then ask before applying each task's changes. Check source preimages again and apply with backups/undo; reject out-of-scope changes, symlinks, drift, and changed gate definitions. Never auto-merge or reset the user's tree. If interrupted, stop for inspection; no automatic resume of uncertain work. Full OS containment, write-ahead transactions and automatic crash recovery are later milestones, not blockers for the map or gate. Private state/backups use owner-only access.

## Patterns, optional offload, and proof

After original-project verification, offer a concise reusable procedure with applicability, limitations, and recorded evidence. Save project-local `.tsmax/skills/<slug>/{pattern.json,SKILL.md}` only after exact-preview approval, through backup/undo. Historical completed tasks remain eligible when later work changes the tree, with an explicit current-source mismatch label and the original verification timestamp/hash. This does not certify current correctness or replace a new task's gate. Suggest at most three bounded lexical matches before planning without loading the entire library. Provider-specific user skill export is deferred.

Optional offload provides summary, handoff and commit-message proposals from supplied text. Preview checks metadata without sending that text; `--run` authorizes one generation. It never applies changes or completes a coding task; subsequent code changes still need the gate. The Ollama adapter requires an installed runtime and validated local GGUF model metadata. It uses numeric loopback sockets without DNS, redirects, environment proxies, cloud-backed models or pull/download calls. Input/output/body limits and request-wide deadlines bound operations. Runtime identity, its own logging/network behavior and concurrent model-tag mutation remain explicit limitations. No llama.cpp execution profile is implemented. The map needs no model or network. No telemetry, analytics, update checks, subscription proxies, account sharing, or rate-limit workarounds. Internet exceptions remain confirmed pinned installs and calls made by the user's own logged-in CLI. Enforce offline check processes and loopback-only UI/offload boundaries; synthetic real-socket tests complement transport unit tests. Live local-model inference is untested.

Ship separate tested commits: foundation, map, verify, plan/run, patterns, optional offload. Each reports normal and network-blocked suite counts and open issues. Tests use fake headless runners, credential canaries, stale-result checks, incremental-index cases, and undo/conflict scenarios. An unavailable network sandbox is reported as unverified, not a pass.

Before making savings claims, benchmark **the map alone**: identical task, repository, selected provider/model, effort and acceptance checks, with versus without `map query`. This measurement is no longer a prerequisite for implementing plan/run. Include build/query time and usage, fresh sessions, repeated paired trials and raw file-read/token evidence; see [MAP-BENCH.md](MAP-BENCH.md). Paid runs need separate approval. Later compare the full multi-page build using plain top model, tokenstretch and MAX. Report tokens, provider-reported cost when available, wall time and quality separately from subscription charges; missing measurements stay unknown. Publish savings only from measured runs. Repository creation or push needs separate approval and a content/history privacy scan.
